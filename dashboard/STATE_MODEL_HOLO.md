# Phases 18 and 19 state model: hologram brain, dial nodes, today-rail dock

Written 2026-11-10, before any code. Approved design: `mockups/brain/index.html` (brain look 6, dock "instrument", all 43 views in `mockups/brain/STATES.md`). Nothing here changes the engine, blocks, router, command or play logic.

## Approach

1. **A third skin, built beside the old one.** New parts live in `dashboard/holo/` (`holo.js`, `holo.css`, `holo.html`). `dashboard/skin/build.py` bundles them into the same `index.html` next to the current Thalamus skin and the Plain page. `html[data-skin]` gets a third value, `holo`. The old Thalamus skin stays selectable until Morgan signs off, then `dashboard/skin/engine.js`, `skin.js`, `skin.css`, `extra.css`, `theme.css` and `skin.html` are deleted in one commit and `holo` becomes the default.
2. **The hard rule is enforced by structure.** The holo bundle runs in its own shadow root and never calls `Eng`, `Brain3D` or any old drawing function, so the old brain, blobs, branches, cards and popups cannot show inside it. A view is wired to a button only after that view is built in the new style; until then the button does not exist in the holo skin.
3. **Plain JS, not React.** The mockup uses React, Tailwind and Babel from CDNs. The real skin is offline-safe inline code, so the mockup is ported: `shape`, `MODEL`, `drawHolo`, `DialNode`, `Tether` and the dock layout become canvas and DOM code with CSS classes that copy the mockup's look (colours, glass, 16 px / 8 px corners, mono caps labels). No new CDN scripts; fonts stay Inter and JetBrains Mono.
4. **Reuse the logic, replace the drawing.** The state and action code in `skin.js` (requests, polling, capture, picker, autofill, block buttons, presence beat) is copied into `holo.js` and kept the same; only what it renders into changes. Endpoints are unchanged.

## UI state (page only; all real state stays on the server)

| UI state     | Values                                         | Notes                                                                                 |

Derived, never stored: brain mood (missed / busy / calm, same rule as today) sets the core's colour and pulse speed; low energy shifts the brain toward violet at half speed; "rail shown" = any class or test today in `classes`.

## Backend asks (need Morgan's OK; both additive, no rule changes)

1. **`dueDate` on each `command.tasks` row** (one field in `command/command.py`, the task menu). Without it the dials cannot show "due this week", the white dots or "next <item>", and branches beyond the top 5 queue items have no date. The page then computes week, soon and next per sector itself.
2. **"Done today" count.** The mission log only carries its last few lines and has no `done` rows today, so counting it would undercount. Proposed: `actions.doneToday` (count of completed Done requests since midnight) from `dashboard/done_actions.py`. Fallback with no backend change: count `done` lines in the mission log and accept undercounting.

## Phase 20: the Strip dock (2026-11-12)

Design: `mockups/dock` (deleted 2026-11-22, in git history)-nov12/index.html`, design A, menu "on the title". Front-end only: same `/api/state`, same endpoints, no new state on the server. The old two-column dock (card, today rail, always-on log, tool pills) is replaced.

**Layout.** `#dockwrap` holds a lip (no box) and the glass bar.
- Lip, left to right: Up next chips, or the status line when there is one (loading, error, a message); then the "following up / saving to" note when set; then "N done today" and the Log link.
- Bar: task zone (`#card`), a hairline, command zone (`#term` with the field and autofill).
- Sheet: opens inside the dock, above the bar. Exactly one at a time, by priority: add-a-task card, answer, mission log, why.
- A thin progress line (`#sprog`) runs along the dock's top edge while a command runs.

**Client state added to `H`** (all in memory, nothing saved): `logOpen`, `whyOpen` (which task id the Why sheet is for). `H.sel` (rail stop) is gone.

**Long titles.** Nothing is cut with "…". When the line does not fit, the due text goes first, then the length; the subject and the class note stay. If it still does not fit, the title wraps to a second line and the bar grows. Whatever was dropped is in the Why sheet.
